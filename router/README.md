# router

Router mode for Claude Code: each turn, subagent and outside-agent call gets a fitting model and effort: more effort where the work needs it (production-code investigation always Opus high), Sonnet for chats that open with a message, translation, lookup, long read, data or test task, Sonnet high for subagents on defined tasks, Haiku for lookups inside subagents, and never a tier below what the work needs. In the evals: answers 15.6% better than always Opus medium, at about 1.2× its spend.

In real use (the author's first 8 days, 2026-11-18 to 25): 1.7% more spend than no router, with the ledger 2% from Claude Code's own transcripts. The goal is to get below the baseline at the same quality, by tuning which effort raises pay. The ledger now records each one (0.9.0).

## Features at a glance

| Feature | What you get |
|---|---|
| Effort per turn | each task gets its class's effort; effort changes keep the prompt cache |
| The chat's model | a cheaper model on the first prompt when 3 Haiku samples agree; never up by itself |
| Quick turns | a sure lookup runs one turn on Haiku, then back |
| Unhappy replies | the 2nd unhappy reply raises effort a step, the 4th again and offers the next model |
| Model tips and session check | switch offers with buttons and what the switch costs |
| Subagents | routed by type or brief: Haiku for lookups, Sonnet high for defined tasks, Opus high for debugging, review, security |
| Ultrathink, ultracode | the router steps aside for that turn and every agent under it, and only measures |
| Reader and researcher | two shipped subagents, sized per brief to Haiku or Sonnet |
| Big pastes | a long paste is read first by a cheaper model; the chat gets the analysis and the file path |
| Keep awake | a hidden nudge keeps an idle chat's cache warm, only while you're likely to come back; off per chat |
| Compact at | your own compaction point per chat, the cheapest one marked, optionally your default |
| Ledger, Stats, Board | spend against no router, saved and extra apart, by chat, project, model and effort; trims itself |
| Units | dollars, or % of your plan's weekly limit |
| Codex, Antigravity | outside second opinions as read-only tools |
| Training data | opt-in: logs each switch the router makes, so you can rate it 👍 or 👎 (👎 goes back) |

Every row is detailed under *What it does* below.

## Install

```
/plugin marketplace add elennaro/claude-router
/plugin install router@claude-router
```

From a local clone instead: `/plugin marketplace add <path to the clone>`.

**Needs:** Claude Code 2.1.325 or newer. Node.js 22.13 or newer on PATH for the ledger (savings, Stats, Board); without it routing still works and one toast says what is missing. Optional: the Codex CLI (`npm install -g @openai/codex`) and Antigravity CLI (`agy`) for the outside-agent tools.

No setup is needed: the built-in rules apply until you add a `~/.claude/routing.json`.

## What it does

| Where | What happens | Who decides |
|---|---|---|
| Effort, every turn | Keyword rules (English only), then Haiku with a confidence score (any language), name a task **class** for each new task of 12+ characters; follow-ups ("ok, do it") keep the current one. The turn's effort follows the class. Class efforts are set for Opus: on Fable, high and above run one step lower (Opus high is Fable medium, Opus xhigh is Fable high). Rules may only raise a tier; a cheaper class needs the classifier. Effort changes keep the prompt cache. | Automatic |
| The chat's model, first prompt | Before anything is cached, 3 Haiku samples read the first prompt. Only if all 3 agree on a cheaper, non-floor class does the chat move (shown as "Picked X for this chat · Undo"). Built in, that is Sonnet for a message to one person (write, fix or translate), mechanical edits, lookups, long reads, data analysis and test writing: the classes where Sonnet medium's answers were accepted as often as Opus medium's. Public copy (posts, landing pages, scripts) stays final copy. A harder task later moves it back. | Automatic down; never up |
| One quick turn | A sure quick task (explore, mechanical) runs its own turn on Haiku, then the chat goes back to its model. Only while that is cheaper: Haiku has to write the whole chat into its own cache, so long chats (past about 100K tokens on Opus) stay on their model. | Automatic |
| Not happy with an answer | After each answer, one Haiku sample reads your request, the end of the answer and your next prompt (any language, no word list) and says whether you are clearly unhappy with it, going on with the same task, or starting a new one. "Sorry", "my bad", "I mean" never count. An unhappy reply keeps the task's class. The first one changes nothing, so one misread costs nothing; the second raises the effort one step for the rest of the task; the fourth raises it again (medium, high, xhigh at most) and shows the model tip for the next model up (Haiku to Sonnet, Sonnet to Opus; never Fable). Effort changes keep the prompt cache. A new task starts calm again. In the eval (44 exchanges, 3 runs): 94% of complaints caught, 100% of new tasks read right, 10.6% of calm replies misread (nearly all "I meant X" after a wrong guess), so about 1% of tasks get a raise they didn't need. | Automatic |
| Model tip | A class that needs a stronger model shows "X fits <class> better" with a **Switch** / **Compact and switch** button, and roughly what switching costs: the new model writes the chat into its own cache once. Never a cheaper model from one prompt. | You |
| Session check | After a compaction, a finished todo list, an approved plan, or every 20 prompts, 3 Haiku samples read the last 8 prompts, the todo list and the plan, and judge the work still ahead. Up needs 2 of 3; down needs 3 of 3, all sure, with no floor task at hand. Lighter, same work: the chat moves by itself ("Picked X for this chat · Undo") only when the move pays back the cost of re-writing the chat into the new model's cache: right after a compaction or an hour's pause (the cache is rebuilt anyway), or when chats like this one usually run on long enough, judged from your past chats (needs 20 of them; before that, once the chat has run as many steps as the switch would take to pay back). Otherwise it stays, and the task's effort does the work. Harder work, or lighter work on a new topic: the band offers **Compact and switch to X** or **Fresh start on X** with the rough switch cost, and **Not now**. Quiet for 10 prompts after an offer, and after Not now until a different trigger. `/route` shows the cache size and what a switch to each model would cost. | Down: automatic when it pays; up: you |
| Subagents | A type in the `agents` table (Explore, Plan) gets its entry. Any other agent with no `model:` in its file (general-purpose, claude, your own) is routed by its brief. A defined task goes to **Sonnet high** (`subagent` in routing.json): a brief no class claims surely, a class at the main tier, and scoped code. Lookups and tiny edits a class is sure of go to Haiku; production debugging, review, security and the floor classes keep Opus high, even when the classifier is unsure; one that must also reproduce the failure (a local repro, a load or stress test) runs a long tool loop and gets Opus xhigh. A brief too short to read runs on the parent's model. Fable is never picked automatically. Forks and resumed agents are never re-routed. The same brief spawned again goes one tier up. Agents of a workflow run are left alone (see the next row). A model on the Agent call or in the agent file always wins. So do the main model's own words in the brief ("use high effort", "use opus"): the Agent call has no effort field, so the brief is where an asked effort lives, and it beats the router's tier. | Automatic |
| Ultrathink, ultracode, workflows | A prompt with "ultrathink" or "ultracode" runs as you set it: no classifier, no tip, no Haiku turn, no router pick of the chat's model, no effort change. Every subagent started in that turn, every agent of a workflow run, and their own subagents run as asked too. Your picks in Settings and your words in the prompt ("use sonnet") still hold. The ledger still counts every step, with its no-router cost equal to what it spent, so these turns show no saving and no extra. Claude Code's session-wide ultracode switch is not visible to plugins: with it on, only the workflow agents are left alone. | You |
| Big pastes | A message of yours over about 10K tokens (a log, a file, a long thread pasted in) is saved to `~/.claude/router/pastes/` and read first by a cheaper model: **Haiku** for finding things in up to about 50K tokens, **Sonnet** for judgment (review, compare, recommend) or more text. The chat gets your words around the paste as typed, that model's analysis (your request, what the material is, the facts it needs with where they are, what was left out) and the file's path, so the main model can read the whole text if the analysis falls short. A toast says when this happens. Put "raw" or "keep it" at the start or end of the message to send it as is. Slash commands and messages that aren't yours (a peer session's, a notification) are left alone. If saving or reading fails, the message goes through as typed with a note. Ledger: the reading counts against the chat's model writing the paste into its cache once (who `paste`); if the main model then reads the saved file, that paste counts as saving nothing. The files are deleted when the session ends, and any left over are swept a day later. | Automatic |
| Keep awake | The main chat's cache lasts an hour after its last step; after that your next message re-reads the whole chat at the cache-write price (about 40 times a cached read). So 50 minutes after the last step (yours, a notification's, or a nudge's) the router sends a one-line nudge (no work, no tools, reply "cache warm") at low effort on the same model, which reads the chat from cache and keeps it warm. The nudge and its reply draw nothing in the transcript (ctrl+o shows the nudge). While a turn is still open, such as a question or a permission dialog waiting on you, no nudge is sent: it could not run before you answer anyway. It goes on every 50 minutes for up to the hours you set (default 12; 2, 4, 8, 12 or 24 in Settings), counted from the chat's last real step, but only while it pays: **before the first nudge** one Haiku sample reads your last message and the end of the answer, and a chat that is clearly finished ("thanks, that's all", "nothing left to do") gets none. **Each idle stretch is remembered** (when the chat went idle and when you came back, or that you have not yet; across chats, in the plugin's store, no text): once 20 have closed, the router knows how likely people are to come back at each hour of the day, and before each nudge it checks whether the nudges still allowed would cost less than the rebuild they could save, given those chances (a nudge is one cached read; a rebuild is about 40 reads on Opus and Sonnet, 80 on Fable). Chats left at night that are rarely picked up again stop being nudged; ones you usually come back to keep going. When it stops for that reason it still compacts the chat into a handoff if you are likely to return later. A notification or another session's message does not count as you coming back. **Off for one chat**: Settings, *This chat*, *Keep awake*, or **Stop for this chat** on the away report. When the window ends it compacts the chat while the cache is still warm, as a handoff (what it was working on, where it stopped, what is left, and a continuation message to send), and stops. While you're away the band says how many nudges ran, what they cost and what re-reading the chat would have cost; the report stays through your first turn back, with what it saved, and your next message clears it. Chats under about 20K tokens are left alone. If a nudge finds the cache already gone (a 5-minute cache, as API keys get), keep-awake turns itself off and says so. If the machine slept past the hour, no nudge is sent: instead, when the chat is big enough that compacting pays back within about 30 steps, the band offers **Compact first** with what resuming costs, what compacting adds and what it saves per step (**Keep it all** or sending a message dismisses it). Ledger: each nudge counts as extra spend (who `awake`); coming back after the cache would have lapsed with no router counts the avoided rebuild as saved. The window's own compaction books no saving yet, since its cost isn't measured. Two weeks of the author's chats: resumes after an hour idle cost about 22% of all spend, and keep-awake for 12 hours would have cut that cost by about 80%. | Automatic |
| Compact at | Your own compaction point for this chat (Settings, *Compact at*, a slider with a mark every 100K): Claude Code (its own window, about 967K on 1M models) or any point from 200K up to the model's own context limit. The track is one gradient both ways from the cheapest point for this chat (green): below it toward purple as compactions come too often (each loses detail; fully purple under 20 steps between them, none from 40), above it through amber to red as it costs more (fully red a quarter over the cheapest). When a turn ends past your point, the router compacts the chat right after it, warm, and says so. The note shows the chat's size, what compacting costs now, how fast this chat grows per step, what a step reads now, and what a step would average if it compacted at the point; the point that averages cheapest for this chat is marked *cheapest*; then, for every point, how many times it would compact and what it would cost per 100 steps. A point past Claude Code's own window needs **Make it my default** to be reached, and the note says so. The math: a chat that compacts at a point sawtooths between about 113K (what a compaction leaves, the author's median) and the point, so each step pays a half-way read plus a share of one compaction (read the chat, write a 5K summary, write what it keeps). **Make it my default** writes the point to `autoCompactWindow` in `~/.claude/settings.json` (every other key kept; a file it can't read is left alone), so Claude Code compacts every new session there itself; `CLAUDE_CODE_AUTO_COMPACT_WINDOW` still beats it. On two weeks of the author's chats, a 300K window would have cut main-chat spend by about 7%. A pick lasts for this chat; Clear resets it. | Your pick |
| Reader and researcher | The plugin ships two agents the main model can pick by their description: **document-reader** (long files, logs, transcripts; Read, Grep, Glob) and **web-researcher** (searches and pages; WebSearch, WebFetch). Before each run the router sizes the brief: the files it names (their size on disk), the pages it names, and whether it asks for judgment (compare, evaluate, recommend, review). Finding work in up to about 50K tokens of files, a search, or up to 3 named pages runs on **Haiku**; judgment, more pages, bigger files, or files it can't size run on **Sonnet**. The brief gets a budget line (how many searches and fetches, a 400-word report with a link or line per finding). With no router the main model would have done the job itself, so these runs are measured against its model. A model on the Agent call or in the brief still wins. | Automatic |
| Hand lookups down | The main model is fixed for a turn, so a search step inside a bigger task would run on it. When subagent routing is on and the Agent tool is offered, the router adds one paragraph to the system prompt: searches and reading across several files, pages or logs go to a subagent with a short brief (then routed as above); judgment, design, code changes and the final writing stay in the main chat; a single quick lookup stays too. | Automatic |
| Codex, Antigravity | The `mcp__router__codex` and `mcp__router__antigravity` tools run them read-only on the newest model of the role's family, with the standard flags. Calling `codex exec` / `agy -p` in Bash is pointed to the tools. | Automatic |

**Floors:** classes marked `floor` in routing.json never get a lower model or effort than the main default.
**Your words win:** "use sonnet", "high effort", "think harder", "run haiku subagents", with "from now on" to keep it for the chat, beat every rule and floor.

## Band and Settings

One row above the prompt: `● Router · ■ <model> <effort> · saved $x`, then on the right `hit N%`, the cache, **Board**, **Stats** and **Settings** (and **Switches** with *Training* on); `$x extra` is in the warning color. The cache is the **Cache** button itself, in the longest words that fit the width: `Cache 96K · 60 min left`, `Cache 96K · 60m`, `60m left`, or just `Cache`; at 10 minutes and under it turns to the warning color, and once the hour is gone it says **Cache expired** at any width. When the row is short of room, parts drop in this order: the hit, then the word "Router" (the dot stays), then **Switches** and **Board** (both stay in the Router panel), and the cache words shorten; the row never wraps to a second line, in a terminal or in the desktop app, whose wider buttons are allowed for. The row never grows with what you open: an offer, a tip or the away report adds one row, nothing else, so the chat doesn't jump and the mouse wheel scrolls the chat. **Cache**, **Stats**, **Settings** and **Switches** open as tabs of one **Router** panel beside the chat (Esc closes it).

All spend is measured against **no router**: the model and effort each request asked for (yours, or the parent chat's for a subagent), at the same tokens. A model reached by pressing a router tip or offer counts as the router's choice: the baseline stays on the chat's model from before that switch, so a move up to Fable shows as extra spend. A model you pick in Settings or name in a prompt is yours, and the baseline follows it. A different effort is priced by its measured cost (a high-effort step about 1.4× a medium one, low about 0.72×). Saved and extra spend are summed apart, so cheap subagents never hide a dearer turn.

**Colors:** Haiku green, Sonnet teal, Opus clay (Claude's own), Fable ruby, the same in Stats, the Board and Settings. A darker shade is a higher effort, in both themes: a light tint for low, the model's own color for medium, darker for high and darker still for max (xhigh shows as max). On a dark page the dark steps get a faint light edge so they stay visible. The palette was checked for color-blind separation and contrast on both themes; names and tooltips always say the model too.

**Cache hit** is the share of prompt tokens read from the prompt cache instead of sent fresh or written to it. High is cheap: a read costs a tenth of fresh input.

- **Cache**: how big the main chat's cache is against the model's limit, the minutes left before it expires (any message, a keep-awake nudge too, starts the hour again), a bar of what is in it (system prompt, tools, memory, messages... as Claude Code reports them) with each part's size, and **what it costs now**, prices in one column: losing the cache (an hour idle), a switch to each other model, compacting now, `/clear` (a new chat writes only the system prompt and tools), and keeping it warm. Under them, keep awake On/Off for this chat, and the away report while there is one.
- **Stats**: this chat against no router (saved and extra), this project across chats, the model and effort now, what this chat cost (the app's own figure) and its cache hit, the **cache** (its size, how many minutes it stays warm, counting down while the card is open, and what rebuilding it costs), **where it went** (the reason that saved most, its saving and the biggest extra), and **keep awake** (what it saved this chat, when the next nudge goes, and what the nudges cost, or why it stopped), and on a Claude plan **Plan** (the weekly and 5-hour limits used, as Claude Code reports them, and what one weekly point cost here). Hover a cell for its full text. Under the cells, one line of what a switch costs right now (each other model writing the chat once), what compacting costs (reading the chat once and writing about 65K back), and that after an hour idle the cache is gone anyway. Under them, **Models this chat**: one band of this chat's spend by model and effort, with each model's share, and how many turns and subagents were re-routed. Then **Cost per turn vs no router**: one bar per turn, up when it cost more than with no router, down when it cost less (square-root scale, so small turns stay visible; hover for exact numbers), in its model's color. Under it, **Cache hit per turn**: a bar per turn in the same column, taller and more solid for a higher hit, scaled by the share that missed in tenfold steps (99.9% full, 99% two thirds, 90% a third), so 99% and 99.9% look different; a missed token costs about 10x a read. Hover a bar or a band segment on the desktop for its numbers. Two columns in a narrow window, four in a wide one.
- **Switches** (only with *Training* on in Settings; off by default): this chat's last 10 switches the router made, newest first: when, who (the chat or a subagent type), from (the model and effort with no router) → to, and the task class. Each gets **👍** or **👎** once. 👍 records the switch as right. 👎 records it as wrong and goes back where something is left to go back to: a chat model the router picked goes back like **Undo** (if re-reading the chat on the old model costs over $0.10, a toast says the price first), and an effort the router chose is pinned back to the chat's own effort (as picking it in Settings; Auto there hands it back). Each only while the chat is still on the router's choice: a model or effort you picked since stays. Model and effort switches are separate entries, each logged once per new from-to; a quick turn logs once per turn; a model or effort you name in the prompt, or an ultrathink turn, is yours and not logged; nor is anything in a `claude -p` run (evals, scripts). A quick turn on Haiku or a subagent run is already over, so its 👎 is only recorded. Neither button waits on anything. A turn the router kept as it would run with no router logs a *stay* row (not in the list), unless you named or picked the model or effort. Your next message labels what the router did on the turn before: an unhappy reply (the mood check) as 👎, a short thanks or "good" (English or Russian, no model call) as 👍; a button press always wins over these. The log goes to the `switches` table in `~/.claude/router/router.db` on this machine only: time, session id, who, kind, from and to model and effort, class, reason, the cost of going back, the label with its source (`button` or `mood`), and for the main chat **the prompt** (reminders stripped, secrets and long tokens masked, up to 2000 characters; a subagent's brief is never kept). To keep it small and balanced, rows you never labelled are trimmed after the day they were made to 2 per labelled row (switches and stays apart). Kept 400 days. It is training data for a local router that will learn from your own use.
- **Board** opens `~/.claude/router/board.html`, filtered by 1d to All: spent, without router, the net in words ("saved $x" or "$x extra"; a sign alone was read backwards) and the cache hit; a line with saved and extra apart; a keep-awake line (how many nudges ran, what they cost and the re-reads they saved); every session (named by its first prompt) with a small band of its models; every project; spend by model (one band, then each model's spend, requests and cache hit); subagents by type; and this chat turn by turn with the model's color and the cache hit. On a phone-width window the less important columns hide.
- **Settings**, in three blocks, each control in one column after its label. **This chat** (kept for this chat, also after a restart; the last 50 chats): *Routing* Off / Effort / Models / Both, which beats the project and Everywhere for this chat only. *Model*: Auto / Haiku / Sonnet / Opus / Fable, each with its color, so the row is also the legend; and *Effort*: Auto / Low … Max. A pick locks this chat to it: the router stops moving the chat and counts savings against your pick; Auto lets it choose per task again. *Keep awake* On/Off. *Compact at*: a slider from the smallest point to the model's limit, coloured as a gradient (purple: compacts too often, green: cheapest, amber to red: dearer), with a mark every 100K and marks for the chat's size now (▲), the cheapest point (★) and Claude Code's own (│). On the desktop it is drawn as a picture over a row of points (Claude Code, then every 100K) to press, each with its cost dot; in a terminal, drag or click it, or ←/→ then Enter; elsewhere, a list. Under it: what a step averages compacting at your point and at the cheapest one, and how fast this chat grows. **This project** (in a project): *Routing* On/Off, which beats Everywhere; turning it or Everywhere on or off clears this chat's own Routing. **Everywhere**: *Units*: Dollars or Plan %: with Plan %, the band and Stats show savings and extra spend as a share of your plan's weekly limit, at the dollars this machine spent this week per point of that limit (it starts once the week has 3 points and $3 of spend; spend elsewhere, such as claude.ai, moves the limit but not the ledger, so the share then reads high; on an API key it stays in dollars). *Move down*, *Helpers*, *Big pastes*, *Keep awake*: On/Off for the four saving features (the automatic move down when the cache rebuild pays, the sized reader and researcher, reading big pastes first, keeping an idle chat warm), and *Keep it for* 2 to 24 hours, with the current cost of a nudge, a rebuild and a compaction in the note, kept for later sessions. *Training*: On/Off (off by default, kept for later sessions) for the switch log and the **Switches** button. *Routing* Everywhere and for the project are written to routing.json; other open sessions follow within about 10 seconds or on their next prompt. **Tools**: update the CLIs. Show or hide the widget, edit the rules.
- **Widget**: the routing now, saved or extra this chat, and once the cache passes 1K tokens its size, what losing it costs and what a switch to each other model costs; then the cost bars.

**After a restart:** which subagents were moved, their spend so far, and this chat's Stats are kept per session in the plugin's own store (the last 30 sessions), so a resumed chat goes on measuring them right. This chat's Routing, Effort, Keep awake and Compact at come back too (the last 50 chats).

**Ledger:** one SQLite file, `~/.claude/router/router.db` (about 20 KB for a busy day), written through node's built-in `node:sqlite` by a small runner the plugin keeps at `~/.claude/router/sqlite.mjs`; node must be on PATH. Five tables: `sessions` (id, project, label), `days` (turns per session per local day), `usage` (steps, spend, no-router cost, extra spend and prompt tokens (fresh, cache read, cache write; from 0.7) per day, session, who and model; who is `main`, `router` for the classifier, or a subagent type) `spawns` (subagent runs, routed, re-spawned) and `efforts` (from 0.9: the same model steps by the effort they ran at, the effort they would have run at with no router, the task class, and why: `class`, `unhappy` for a raise after unhappy replies, `pick`, `asked`, `agent`, `nudge` or `as-is`), so extra spend can be traced to the class or raise that bought it. The ledger trims itself at each session start: effort detail after 60 days, everything else after 400 (the Board goes back a year). Extra spend by class and reason: `SELECT cls, why, effort, asked, round(sum(extra), 2) AS extra, round(sum(base - usd + extra), 2) AS saved FROM efforts WHERE who = 'main' GROUP BY 1, 2, 3, 4 ORDER BY extra DESC`. Rows are batched and saved about every 2 s and at the session's end; if a save fails, the rows wait for the next one. Query it with any SQLite tool. The only text kept is the first 60 characters of a chat's first prompt, which names it on the Board (injected reminders dropped, long tokens such as keys masked); no other prompt or brief text is stored. A `/clear` starts a new session row. The Haiku classifier's cost counts as extra spend. Rows from before 0.5 were measured against the main model and have no extra split. Prices are API-equivalent; on a Max plan they track limit usage, not money.

**Checking the savings:** `node bin/check-savings.mjs [days | YYYY-MM-DD]` re-counts each session's spend from Claude Code's own transcripts, with its own price code, and prints it next to the ledger's spend, no-router cost, saved and extra. The two spend columns should agree within a few percent; a bigger gap means steps were missed or counted twice. Prices follow the pricing page: main-chat cache writes are 1-hour entries (2× input), subagent writes 5-minute ones (1.25×). A run a re-spawn replaced counts as saving nothing. `--test` checks the script itself. On the author's first 8 days of real use (2026-11-18 to 25): ledger and transcripts 2% apart; $1,898 spent against $1,867 with no router, so 1.7% more, with $73 saved and $104 extra (mostly raised effort on Opus turns).

**Net** is saved minus extra, so a longer range can show a smaller net saving than a shorter one inside it, when the added days ran extra. Saved and extra on their own only grow with the range.

**Widget:** a two-row glance over the cost bars. Turn it on in Settings, then drag it into the session rail (a mod can't place it there).

`/route status` · `/route board` · `/route widget` · `/route on|off` (this chat) · `/route effort on|off` · `/route models on|off` · `/route effort retest` · `/route reload` (after editing routing.json).

## Configuration

`~/.claude/routing.json` holds the defaults. A project's `.claude/routing.json` overrides any key; the maps (`classes`, `agents`, `keywords`) merge per entry.

```json
{
  "keywords": { "structure": ["beat plan", "episode plan"] },
  "agents": { "probe-agent": { "class": "mechanical" } }
}
```

For a production codebase, raise the project's default: classes that sit at the default (explain, docs, data analysis, long reads and others) follow it, so a production log read or an "explain why this fails" gets Opus high even when neither the rules nor the classifier see debugging in it. Do this if you write prompts in a language other than English: the keyword rules are English only, and when Haiku is unsure such a prompt runs at the default (in the evals, 3 production prompts in Russian out of 279 cases).

```json
{ "main": { "model": "opus", "effort": "high" } }
```

## Tools

- `node bin/pin-agents.mjs <agentsDir> '<json>' [--fill] [--dry]` pins `model:`/`effort:` in agent files.
- `../evals/`: the eval suites (per prompt, session check, subagents) and their reports.

## Limits (Claude Code 2.1.325)

- `claude -p --agent X` ignores the agent file's `effort:`; pass `--effort`.
- Headless runs (`claude -p`, no surface) are counted, never re-routed. Desktop-app sessions start the same way and switch to routed once the app attaches.
- A subagent's "parent model" is the session's model, not a one-turn move. The Sonnet default only ever lowers: on a Sonnet or Haiku session an unsure brief gets the main default (Opus) instead.
- Code mode (experimental, `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE`) does not start while the router is installed: it refuses any plugin that hooks tool calls or subagent spawns, and the router hooks both (checked in Claude Code 2.1.323). Disable the plugin for a code-mode session.
